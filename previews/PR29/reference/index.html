BufferIO.AbstractBufReader — Type
abstract type AbstractBufReader end

An AbstractBufReader is a readable IO type that exposes a buffer of readable bytes to the user.

Warning

By default, subtypes of AbstractBufReader are not threadsafe, so concurrent usage should protect the instance behind a lock.

Extended help

Subtypes of this type should not have a zero-sized buffer which cannot expand when calling fill_buffer.

Subtypes T of this type should implement at least:

  • get_buffer(io::T)
  • fill_buffer(io::T)
  • consume(io::T, n::Int)
  • Base.close(io::T)
  • Base.isopen(io::T)

Subtypes may optionally define the following methods. See their docstring for BufReader / BufWriter for details of the implementation:

  • Base.seek(io::T, ::Int)
  • relative_seek(io::T, ::Int)
  • Base.filesize(io::T)
  • Base.position(io::T)
  • resize_buffer(io::T, ::Int)
  • BufferIO.is_expandable(::Type{T})

AbstractBufReaders have implementations for many Base IO methods, but with more precisely specified semantics than for Base.IO. See docstrings of the specific functions of interest.

BufferIO.AbstractBufWriter — Type
abstract type AbstractBufWriter end

An AbstractBufWriter is an IO-like type which exposes mutable memory to the user, which can be written to directly. This can help avoiding intermediate allocations when writing. For example, integers can usually be written to buffered writers without allocating.

Warning

By default, subtypes of AbstractBufWriter are not threadsafe, so concurrent usage should protect the instance behind a lock.

Extended help

Subtypes of this type should not have a zero-sized buffer which cannot expand when calling grow_buffer.

Subtypes T of this type should implement at least:

  • get_buffer(io::T)
  • grow_buffer(io::T)
  • consume(io::T, n::Int)
  • Base.close(io::T)
  • Base.isopen(io::T)
  • Base.flush(io::T)

They may optionally implement

  • Base.seek(io::T, ::Int)
  • Base.filesize(io::T)
  • Base.position(io::T)
  • get_unflushed(io::T)
  • shallow_flush(io::T)
  • resize_buffer(io::T, ::Int)
  • get_nonempty_buffer(io::T, ::Int)

BufferIO.BufReader — Type
BufReader{T <: IO} <: AbstractBufReader
BufReader(io::IO, [buffer_size::Int])::BufReader

Wrap an IO in a struct with a new buffer, giving it the AbstractBufReader interface.

The BufReader has an infinitely growable buffer, which may grow when fill_buffer is called.

When filling its buffer, the BufReader may move the buffered bytes to the beginning of its internal memory to make room for new bytes. This compaction is guaranteed to be amortized O(n_bytes_read), no matter how calls to fill_buffer and consume are interleaved.

This wrapper reads from io using readbytes!. If io is not EOF, and readbytes! reads zero bytes, an exception is thrown when filling the buffer.

Throw an ArgumentError if buffer_size is less than 1.

julia> rdr = BufReader(IOBuffer("Hello, world!\nabc\r\ndef"));

julia> get_buffer(rdr) |> isempty
true

julia> peek(rdr)
0x48

julia> readline(rdr)
"Hello, world!"

julia> String(readavailable(rdr))
"abc\r\ndef"

Extended help

For an io::Base.IO type to function correctly when wrapped in a BufReader, it must implement:

  • eof(io)::Bool, which may block until at least one byte is available or EOF is known. If this returns false, at least one byte must be available to read.
  • Either readbytes!(io, v::MutableMemoryView{UInt8})::Integer, or else unsafe_read(io, ::Ptr{UInt8}, ::UInt) and bytesavailable(io)::Integer. If readbytes! are implemented, it should read at least one byte when eof(io) === false.

Seeking, and filesize and position of the BufReader, additionally require io to implement seek, filesize and position.

julia> io = IOBuffer();

BufferIO.BufWriter — Type
BufWriter{T <: IO} <: AbstractBufWriter
BufWriter(io::IO, [buffer_size::Int])::BufWriter

Wrap an IO in a struct with a new buffer, giving it the AbstractBufWriter interface.

The BufWriter has an infinitely growable buffer, and will only expand the buffer if grow_buffer is called on it while it does not contain any data (as shown by get_unflushed).

Throw an ArgumentError if buffer_size is < 1.

julia> io = IOBuffer(); wtr = BufWriter(io);

julia> print(wtr, "Hello!")

julia> write(wtr, [0x34, 0x12, 0x78, 0x56])
4

julia> isempty(read(io)) # wtr not flushed
true

julia> flush(wtr); seekstart(io); String(read(io))
"Hello!4\x12xV"

julia> isempty(get_unflushed(wtr))
true

Extended help

For an io::Base.IO type to function correctly when wrapped in a BufWriter, it must implement:

  • close(io)
  • flush(io)
  • unsafe_write(io, ::Ptr{UInt8}, ::UInt)

Seeking, and filesize and position of the BufWriter, additionally require io to implement seek, filesize and position, where:

  • Writing overwrites existing data, and seeking does not truncate io.
  • filesize(io) includes any data written to io beyond position(io). For example, IOStream meets this, because it writes out its own buffer when seeking.

Seeking is not supported if io is in append mode (e.g. a file opened with append = true), because then io ignores its position when writing.

BufferIO.ExpandReader — Type
ExpandReader{T <: AbstractBufReader} <: AbstractBufReader

Reader which wraps another reader and provides an infinitely expandable buffer. ExpandReader forwards its inner reader's buffer where possible, but if fill_buffer is called and the inner reader can't expand its buffer, ExpandReader will serve the data from its own growable buffer. This implies that fill_buffer(::ExpandReader) always returns an Int, never nothing.

ExpandReader is useful when users need to buffer a minimum amount (e.g. an entire line, or N bytes), but want to read from a generic AbstractBufReader. Generic code may use the expandable function to opt-into ExpandReader only when necessary.

ExpandReader takes control of the inner reader, and mutating the inner reader may invalidate the ExpandReader.

See also: expandable, BufferIO.is_expandable

Examples

julia> using BufferIO.Testing: BoundedReader

julia> inner = BoundedReader("Hello, world!", 4; max_fill = 4);

julia> fill_buffer(inner); fill_buffer(inner) === nothing # inner can't grow its buffer
true

julia> reader = ExpandReader(inner); # In generic code, prefer `expandable(inner)`

julia> String(get_buffer(reader)) # inner's buffer is forwarded
"Hell"

julia> while !iszero(fill_buffer(reader)) end

julia> String(get_buffer(reader)) # served from the own buffer of `reader`
"Hello, world!"

julia> BufferIO.is_expandable(typeof(reader))
true

BufferIO.VecWriter — Type
VecWriter <: AbstractBufWriter

A writer that appends to a Vector{UInt8}, which is stored in the (public) property .vec.

This type is useful as an efficient string builder through takestring!(io).

Functions flush and close do not affect the writer.

Mutating io will mutate vec and vice versa. Neither vec nor io will be invalidated by mutating the other, but doing so may affect the implicit (non-semantic) behaviour (e.g. memory reallocations or efficiency) of the other. Mutating vec invalidates buffers previously obtained from io with e.g. get_buffer.

Create with one of the following constructors:

  • VecWriter()
  • VecWriter(undef, n::Int): Create an empty vector with space for at least n bytes
  • VecWriter(vec::Vector{UInt8}): Append to vec, which is not copied.

A VecWriter has no notion of filesize, and cannot be seeked. Instead, resize the underlying vector io.vec.

julia> vw = VecWriter();

julia> write(vw, "Hello, world!")
13

julia> append!(vw.vec, b" More data");

julia> takestring!(vw)
"Hello, world! More data"

julia> v = collect(b"abc");

julia> write(VecWriter(v), "def");

julia> String(v)
"abcdef"
BufferIO.consume — Function
consume(io::Union{AbstractBufReader, AbstractBufWriter}, n::Int)::Nothing

Remove the first n bytes of the buffer of io. Consumed bytes will not be returned by future calls to get_buffer.

If n is negative, or larger than the current buffer size, throw an IOError with ConsumeBufferError kind. This check is a boundscheck and may be elided with @inbounds.

Examples

julia> reader = CursorReader("abcdefghij");

julia> get_buffer(reader) == b"abcdefghij"
true

julia> consume(reader, 8); get_buffer(reader) |> println

julia> consume(reader, 3) # 2 bytes remaining
ERROR: Called `consume` with a negative amount, or larger than available buffer size
BufferIO.discard — Method
discard(io::AbstractBufReader, n::Int)::Int

Read n bytes from io, or until EOF, whichever comes first, and discard the read bytes. Return the number of bytes discarded.

This function is defined generically for AbstractBufReader by reading bytes, not by seeking, so it works on readers that can't seek. Subtypes of AbstractBufReader may implement this using seeking.

Throw an ArgumentError if n < 0.

See also: discard_exact

julia> read(reader, 3) |> String

julia> discard(reader, 10) # 2 bytes remaining

julia> eof(reader)

julia> discard(reader, 100)

BufferIO.drop_own — Method
drop_own(io::ExpandReader)::Union{Nothing, Memory{UInt8}}

If the own buffer of io is in use or io is closed, return nothing. Else, drop the buffer from io, and return it. The returned memory may be empty, and is owned by the caller, i.e. io is guaranteed to not keep a reference to it.

Since ExpandReaders allocate new buffers as needed, this function does not change the semantic behaviour of io, only its allocation patterns, and never puts io in an invalid state. It is intended to free memory if extra buffering is only transiently needed.

Whether this function returns nothing or the buffer depends on which buffer is used by io, which is an implementation detail.

Examples

julia> io = ExpandReader(CursorReader("Hello, world!"));

julia> String(read(io, 5))
"Hello"

julia> mem = drop_own(io);

julia> mem isa Union{Nothing, Memory{UInt8}}
true

julia> String(read(io)) # dropping does not change the content of io
", world!"
BufferIO.expandable — Method
expandable(io::T)::Union{T, ExpandReader{T}} where {T <: AbstractBufReader}

Return io unchanged if BufferIO.is_expandable(typeof(io)), else wrap io in an ExpandReader and return it. The type of the result is guaranteed to have is_expandable return true, which means its buffer size is able to grow until EOF. Equivalently, calling fill_buffer on the result will not return nothing.

This function is useful when working with non-expandable readers, or generic readers, where the maximum buffer size is unknown, and where some minimum buffering is required. An example could be a reader that wraps a generic AbstractBufReader, and must be able to buffer a full line of input.

The concrete return type of expandable(io) is resolved at compile time.

See also: BufferIO.is_expandable

Examples

julia> io = BufReader(IOBuffer("abc"));

julia> expandable(io) === io # BufReader is already expandable
true

julia> io = BufferIO.Testing.BoundedReader("abc", 2);

julia> expandable(io) isa ExpandReader
true
BufferIO.fill_buffer — Function
fill_buffer(io::AbstractBufReader)::Union{Int, Nothing}

Fill more bytes into the buffer from io's underlying buffer, returning the number of bytes added. After calling fill_buffer and getting n, the buffer obtained by get_buffer should have n new bytes appended.

This function may move data in the internal buffer, invalidating previous buffers obtained by get_buffer. However, data present in previous results from get_buffer must be present in the new buffer at the same indices. In other words, the following must always hold:

old_buffer = copy(get_buffer(io))
fill_buffer(io)
@assert get_buffer(io)[1:length(old_buffer)] == old_buffer

This function must fill at least one byte, except

  • If the underlying io is EOF, or there is no underlying io to fill bytes from, return 0
  • If the buffer is not empty, and cannot be expanded, return nothing.

Buffered readers which do not wrap another underlying IO, and therefore can't fill its buffer should return 0 unconditionally. This function should never return nothing if the buffer is empty.

Note

Idiomatically, users should not call fill_buffer when the buffer is not empty, because doing so may force growing the buffer instead of letting io choose an optimal buffer size. Calling fill_buffer with a nonempty buffer is only appropriate if, for algorithmic reasons you need io itself to buffer some minimum amount of data.

Examples

julia> reader = CursorReader("abcde");

julia> fill_buffer(reader) # CursorReader can't fill its buffer
0

julia> reader = BufReader(IOBuffer("abcde"), 3);

julia> length(get_buffer(reader)) # buffer of BufReader initially empty
0

julia> fill_buffer(reader)
3

julia> length(get_buffer(reader)) # now must be 0 + 3
3

BufferIO.get_nonempty_buffer — Method
get_nonempty_buffer(
    io::AbstractBufWriter, min_size::Int
)::Union{Nothing, MutableMemoryView{UInt8}}

Get a buffer of at least max(min_size, 1) bytes, or nothing if io cannot provide a buffer of that size. The desired buffer length is obtained by repeatedly calling grow_buffer.

Writers whose buffer can grow without bound, such as VecWriter and BufWriter, never return nothing.

Use of this method may cause excessive buffering without flushing, which is less memory efficient than calling the one-argument method and flushing in a loop.

Extended help

Subtypes of AbstractBufWriter may implement this method if they can provide a large buffer more efficiently than the generic fallback. The returned buffer must contain at least max(min_size, 1) bytes.

Examples

julia> using BufferIO.Testing: BoundedWriter

julia> length(get_nonempty_buffer(writer, 3)) ≥ 3
true

julia> get_nonempty_buffer(writer, 5) === nothing # buffer can hold at most 4 bytes
true

julia> length(get_nonempty_buffer(VecWriter(), 100)) ≥ 100 # VecWriter can always grow
true

BufferIO.get_unflushed — Method
get_unflushed(io::AbstractBufWriter)::MutableMemoryView{UInt8}

Return a view into the buffered data already written to io and consumed, but not yet flushed to its underlying IO.

Bytes not appearing in the buffer may not be completely flushed if there are more layers of buffering in the IO wrapped by io. However, any bytes already consumed and not returned in get_unflushed should not be buffered in io itself.

Mutating the returned buffer is allowed, and should not cause io to malfunction. After mutating the returned buffer and calling flush, values in the updated buffer will be flushed.

This function has no default implementation and methods are optionally added to subtypes of AbstractBufWriter that can fullfil the above restrictions.

Examples

julia> io = IOBuffer(); writer = BufWriter(io);

julia> isempty(get_unflushed(writer))
true

julia> write(writer, "abc"); unflushed = get_unflushed(writer);

julia> println(unflushed)
UInt8[0x61, 0x62, 0x63]

julia> unflushed[2] = UInt8('x')
0x78

julia> flush(writer); take!(io) |> println
UInt8[0x61, 0x78, 0x63]

julia> get_unflushed(writer) |> isempty
true
BufferIO.grow_buffer — Method
grow_buffer(io::AbstractBufWriter)::Int

Increase the amount of bytes in the writeable buffer of io if possible, returning the number of bytes added. After calling grow_buffer and getting n, the buffer obtained by get_buffer should have n more bytes.

The buffer is usually grown by flushing the buffer, expanding or reallocating the buffer. If none of these can grow the buffer, return zero.

Note

Idiomatically, users should not call grow_buffer when the buffer is not empty, because doing so forces growing the buffer instead of letting io choose an optimal buffer size. Calling grow_buffer with a nonempty buffer is only appropriate if, for algorithmic reasons you need io buffer to be able to hold some minimum amount of data before flushing.

Examples

julia> v = VecWriter(undef, 0); get_buffer(v) |> isempty
true

julia> n_grown = grow_buffer(v); n_grown > 0
true

julia> length(get_buffer(v)) == n_grown
true
BufferIO.is_expandable — Method
is_expandable(T::Type{<:AbstractBufReader})::Bool

Trait function that signals if fill_buffer on instances of type T never returns nothing. That is, a type T must only implement is_expandable(::Type{T}) = true if fill_buffer(::T) returns an Int for every instance of T.

In practice, this means instances of T are able to buffer their entire content with repeated calls to fill_buffer. Types for which this returns true either already buffer their whole content (such as CursorReader), or else have a growable buffer large enough to hold all the underlying data (such as BufReader or ExpandReader).

This is a property of the type, not of the instance, and must be constant foldable. It is usually implemented as a constant true. The default is is_expandable(::Type{<:AbstractBufReader}) = false.

Readers that wrap another reader and forward its buffer, e.g. a type Wrapper{T}, can typically only grow their buffer if the inner reader can. Such types should usually forward the trait instead of returning true:

BufferIO.is_expandable(::Type{Wrapper{T}}) where {T} = BufferIO.is_expandable(T)

See also: expandable

Examples

julia> BufferIO.is_expandable(BufReader)
true

julia> BufferIO.is_expandable(CursorReader)
true

julia> struct FooReader <: AbstractBufReader end

julia> BufferIO.is_expandable(FooReader) # default is false
false
BufferIO.line_views — Method
line_views(x::AbstractBufReader; keep::Bool=false)::LineViewIterator{typeof(x)}

Create an iterator of lines of x. The returned views are ImmutableMemoryView{UInt8} into x's buffer. Use StringView to turn the lines into AbstractStrings.

The views may be invalidated when mutating x, which may happen on subsequent iterations of the iterator. See extended help for more precise semantics.

If keep is false (the default), the final trailing \r\n or \n bytes are removed from each line.

Examples

julia> lines = line_views(CursorReader("abc\r\ndef\n\r\ngh"));

julia> first(lines) |> String
"abc"

julia> first(lines) == b"abc"
true

julia> first(iterate(lines, 9)) |> String
""

julia> sum(length, lines)
2

julia> isempty(lines)
true

Extended help

A line is defined as all data up to and including \n (0x0a) or \r\n (0x0d 0x0a), or the remainder of the data in io if no \n byte was found. If the input is empty, this iterator is also empty.

If x has a limited buffer size, and cannot grow its buffer, and an entire line cannot be kept in the buffer, an IOError is thrown, with its kind being IOErrorKinds.BufferTooShort. To iterate lines of any length from such a reader, use line_views(expandable(x)).

The resulting iterator will NOT close x when exhausted, this must be handled elsewhere.

Iterator state and io advancement

The resulting iterator itr::LineViewIterator's state is guaranteed, public interface:

  • iterate(itr) is equivalent to iterate(itr, 0)
  • iterate(itr, n::Int) is equivalent to consume(itr.reader, n); iterate(itr) if n > 0
  • The state returned by iterate is an Int equal to the length of the line emitted, plus the number of stripped \r\n or \n bytes, unless keep.

These semantics together mean that a normal for-loop will exhaust the underlying io, and that no emitted line will be invalidated before the next call to iterate.

As an example, to read two lines, one may do:

# Read first line, and do something  with it
(line_1, s) = iterate(itr);    x = process(line_1)
# Two argument iterate advances itr to the begining of next line.
(line_2, s) = iterate(itr, s); y = process(line_2)
# Advance iterator from second line to third line
consume(itr.reader, s) # .reader is a public property

Return a stateless iterator of the lines in x. The returned views are ImmutableMemoryView{UInt8} views into x. Use StringView to turn them into AbstractStrings.

BufferIO.relative_seek — Method
relative_seek(io::AbstractBufReader, delta::Int) -> io

Seek the stream by delta relative to the current position. Seeking by a positive delta will advance the stream, and a negative delta rewinds the stream. When delta is zero, the stream is unchanged.

Seeking beyond either end of the stream will throw an IOError of kind BadSeek.

This method can be faster than seek, because it does not require io to query its absolute position, and therefore, in certain circumstances, the seeking can occur purely in-memory without interacting with the underlying IO.

BufferIO.take_inner — Function
take_inner(io)

Close io without closing the inner io wrapped by io, and return the inner io.

If io is a writer, any data buffered in io is first written to the inner io, so no written data is lost. The inner io is not flushed.

As with close, io should not be used after calling take_inner, and isopen(io) returns false, unless io remains usable. In particular, operations on io may mutate the wrapped IO, and so may invalidate it. Calling take_inner on an io which is closed, or whose wrapped IO has already been taken, is not allowed.

Implementations may, but are not required to, detect and prevent using io after take_inner, or calling take_inner on a closed io, by throwing an IOError of kind ClosedIO.

Examples

julia> cursor = CursorReader("abc");

julia> reader = IOReader(cursor);

julia> take_inner(reader) === cursor
true

BufferIO.unsafe_read_all! — Method
unsafe_read_all!(io::AbstractBufReader, ref, nbytes::Int)::Int

Copy bytes from io into ref (converted to a pointer) until either nbytes bytes are copied or io is EOF, returning the number of bytes copied. This is the unsafe counterpart of read_all!.

Throw an ArgumentError if nbytes is negative.

ref is converted to a pointer as follows:

  • If ref is a Ref{T}: cref = Base.cconvert(Ref{T}, ref), then Base.unsafe_convert(Ref{T}, cref), cast to Ptr{UInt8}. Hence, T may be any bitstype. Throw an ArgumentError if T is not a bitstype, unless ref is a Ptr.
  • Otherwise: cref = Base.cconvert(Ptr, ref), then Base.unsafe_convert(Ptr{UInt8}, cref).

Safety: The user must ensure that

  • The resulting pointer is valid, and points to at least nbytes of writeable memory. For a Ref{T} that is not a Ptr, this means nbytes must not exceed sizeof(T).
  • GC.@preserveing cref correctly pins ref in memory, i.e. the pointer will not become invalid during the GC.@preserve block.

Examples

julia> reader = CursorReader("abcdef");

julia> ref = Ref((0x00, 0x00));

julia> unsafe_read_all!(reader, ref, 2)
2

julia> ref[] == (UInt8('a'), UInt8('b'))
true

julia> v = zeros(UInt8, 8);

julia> GC.@preserve v unsafe_read_all!(reader, pointer(v), 8) # 4 bytes remaining
4

julia> String(v[1:4])
"cdef"

BufferIO.IOErrorKinds.IOErrorKind — Type
IOErrorKind

Enum indicating what error was thrown. The current list is non-exhaustive, and more may be added in future releases. The integral value of these enums are subject to change in minor versions.

Current errors:

  • ConsumeBufferError: Occurs when calling consume with a negative amount of bytes, or with more bytes than length(get_buffer(io))
  • EOF: Occurs when trying a reading operation on a file that has reached end-of-file
  • BufferTooShort: Thrown by various functions that require a minimum buffer size, which the io cannot provide. This should only be thrown if the buffer is unable to grow to the required size, and not if e.g. the buffer does not expand because the io is EOF.
  • WriterFull: Occurs when a writer cannot make room for more data, i.e. when grow_buffer returns zero, such that a write operation cannot complete. If a writer can make room, but not a contiguous buffer of a required minimum size, BufferTooShort is thrown instead.
  • BadSeek: An out-of-bounds seek operation was attempted
  • ClosedIO: Indicates an operation was done on a closed IO.

Copy one line from from to out, returning out. A line is defined as data up to and including \n (byte 0x0a), or all remaining data in from if no such byte is present.

Base.close — Method

Base.filesize — Method
filesize(io::AbstractBufWriter)::Int

Get the size, in bytes, of the data written to io, including data which has been committed with consume, but not yet flushed. This is the size the underlying file or IO will have once io is flushed, provided nothing else modifies it.

0:filesize(io) is the range of valid offsets for seek, and position(io) is always in this range. Writing beyond the end of the data increases the filesize. Other operations, including seeking and flushing, do not change it.

julia> write(io, "xyz"); filesize(io)

Testing utilities

BufferIO.Testing — Module
module BufferIO.Testing

Minimal implementations of AbstractBufReader and AbstractBufWriter intended for testing code that is generic over buffered readers and writers, similar in spirit to Test.GenericString.

The types in this module implement only the required interface methods, and have deliberately restricted buffers. This exercises the code paths that BufReader or VecWriter never hit, such as fill_buffer returning nothing, and fallback definitions of optional methods. Furthermore, BoundedReader overwrites its old buffer whenever views of its buffer may be invalidated, which helps to catch code that uses such views after they have been invalidated.

These types are not optimized for performance, and should only be used in tests.

See also: BoundedReader, BoundedWriter

BufferIO.Testing.BoundedReader — Type
BoundedReader(data, max_buffer_size::Int; max_fill::Int = 1) <: AbstractBufReader

Reader of the bytes of data, whose buffer can hold at most max_buffer_size bytes, and where each call to fill_buffer adds at most max_fill bytes. data can be any object x which implements ImmutableMemoryView{UInt8}(x).

When the buffer holds max_buffer_size bytes, fill_buffer returns nothing, and so BufferIO.is_expandable(BoundedReader) is false. This makes BoundedReader useful to test that generic code correctly handles readers with a limited buffer size, and, with a small max_fill, readers which fill their buffer in small increments.

Views returned by get_buffer are invalidated by fill_buffer, consume and close. To catch code which nonetheless uses such views, every call to these functions moves the buffer to new memory, and overwrites the old memory by flipping all bits of every byte. Hence, invalidated views will appear to contain different data. The bytes of data itself are never modified.

BoundedReader only implements the methods required of an AbstractBufReader, so optional methods such as seek and position are unsupported or use the generic fallback definitions.

Examples

julia> using BufferIO.Testing: BoundedReader

julia> reader = BoundedReader("abcdefg", 4; max_fill = 3);

julia> fill_buffer(reader), fill_buffer(reader), fill_buffer(reader)
(3, 1, nothing)

julia> buffer = get_buffer(reader); String(buffer)
"abcd"

julia> consume(reader, 3); buffer == b"abcd" # buffer invalidated by consume
false

julia> String(read(reader))
"defg"

julia> BufferIO.is_expandable(BoundedReader)
false
